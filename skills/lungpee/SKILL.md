## 1. กฎเหล็ก 2 เครื่อง (ทุก repo)
1. **เริ่มงาน → pull ก่อนแตะไฟล์:** `git -C <repo> pull --rebase --autostash`
2. **จบงาน → commit + push ทันที** ในรอบเดียวกัน ไม่รอให้สั่ง (เว้นลุงพีบอก "ไว้ทีหลัง") · ห้ามทิ้ง commit ค้างเครื่องเดียว
3. diverged → `pull --rebase --autostash` · **CONFLICT → หยุดถาม** ห้าม `--force`
4. commit เฉพาะไฟล์ที่ตัวเองแก้ — ไฟล์ค้างจากงานอื่นอย่าแตะ
5. งานทำบน home ส่งกลับ laptop: ใส่หมายเหตุใน commit + สรุป (ทำบน C: · มี path ต้องปรับไหม · ไฟล์นอก git ที่ต้องคัดลอกเอง · laptop ต้องทำอะไรต่อ)

## 2. ทุกครั้งที่แก้โปรแกรม
- **bump เวอร์ชัน + CHANGELOG** "โดย ลุงพี" (คง created เดิม · ใส่ updated) — Design Auto ใช้ `py <ไดรฟ์>:\LocalAI\bump_version.py designauto <patch|minor|major> "สรุปไทย"` · โปรแกรมไม่มีไฟล์เวอร์ชัน = สร้าง `VERSION.json` + `CHANGELOG.md` เริ่ม 1.0.0
- เว็บที่ import โมดูลแบบ `?v=x.y.z` → เปลี่ยนเลขให้ตรงเวอร์ชันใหม่ (กันแคชเบราว์เซอร์)
- **ทดสอบจริงก่อนบอกว่าเสร็จ:** เทสต์ของโปรแกรม + ลองในเบราว์เซอร์/แอปจริง (ลาก พิมพ์ คลิก) · เทสต์ที่พังอยู่ก่อนแล้วให้ย้อนโค้ดพิสูจน์ แล้วรายงานตรง ๆ
- **แสดงตัวอย่างก่อน แล้วค่อย bump → build → commit → deploy** (ลุงพีสั่ง 5 พ.ย. 2569): ฟีเจอร์/หน้าตาใหม่ ให้ทำในโค้ดแล้วเปิดให้ดูในพรีวิว dev ก่อน (ภาพหน้าจอ + วิธีลอง) → หยุดรอลุงพีตรวจ → อนุมัติแล้วจึง bump เวอร์ชัน · build · commit + push · deploy · ห้าม bump/commit/deploy ก่อนลุงพีเห็นตัวอย่าง
- **ทำให้ตรงกับหน้าตัวอย่างที่ลุงพีอนุมัติทุกส่วน** (ลุงพีสั่ง 2 พ.ย. 2569 — ห้ามพฤติกรรมนี้เด็ดขาด): ตัวอย่างที่อนุมัติ = สเปกที่ต้องส่งครบ ไม่ใช่แค่แนวทาง
  · ห้ามทำบางส่วนแล้วรายงานว่า "เสร็จ" · ห้ามย้ายสิ่งที่อยู่ในตัวอย่างไป "เฟส 2 / ยังไม่ทำ" เอง · ห้ามเปลี่ยนเลย์เอาต์/หน้าตาที่ออกแบบไว้เป็นของง่ายกว่าโดยไม่บอกก่อนลงมือ
  · ก่อนลงมือ: แตกตัวอย่างเป็นรายการ (ทุกปุ่ม ทุกแผง ทุกเลย์เอาต์ ทุกหน้าตา) · ก่อนสรุป: เทียบทีละรายการกับของจริงในเบราว์เซอร์ แนบผลว่าตรง/ไม่ตรง
  · ส่วนที่ทำไม่ได้จริงทางเทคนิค ต้องบอกลุงพี**ก่อน**ลงมือพร้อมเหตุผล ไม่ใช่บอกตอนสรุปท้าย · ถ้าทำไม่ครบในรอบเดียว ให้ทำต่อจนครบ ไม่หยุดถามระหว่างทาง
- **แก้หลายงานพร้อมกัน (หลาย session · checkout เดียวกัน) → ก่อนปล่อยตรวจให้ละเอียดว่ามีโค้ดค้างจากงานไหนบ้าง แล้วรวมปล่อยพร้อมกันให้ครบ** (ลุงพีสั่ง 7 พ.ย. 2569)
  · ก่อน bump: `git status` + `git diff --stat` ทุกไฟล์ · ดูสถานะทุก session ที่เกี่ยวข้อง (ทำงานอยู่/ค้าง/รออนุมัติ) และบันทึกรอปล่อยของแต่ละงาน
  · แจกแจงว่าไฟล์/ส่วนไหนเป็นของงานไหน · งานที่แก้ไฟล์ร่วมกัน (เช่น `app.ts` · `i18n.ts`) ต้องปล่อยรอบเดียวกัน ห้ามแยก commit ด้วยการตัดบางส่วน
  · รวมทุกงานที่ลุงพีอนุมัติแล้วไว้ในรอบเดียว (bump ครั้งเดียว · CHANGELOG ครบทุกงาน) · งานที่ยังไม่อนุมัติ → ถามลุงพีก่อนว่าจะรวมหรือรอ ห้ามปล่อยออกไปเงียบ ๆ
  · หลังปล่อย: ตรวจว่า working tree เหลือเฉพาะไฟล์ที่ห้าม commit (เช่น `out/usermanual/_pdfs.json` · `scripts/sync-home-gui.ps1`) และแจ้งทุก session ว่าปล่อยแล้วในรุ่นไหน
- **เว็บที่ขึ้น GitHub Pages: ทดสอบบนเว็บจริงทุกครั้งก่อนปิดงาน** (ลุงพีสั่ง 2 พ.ย. 2569) — push แล้วรอ deploy เสร็จ (`gh run watch`) → เปิด URL GitHub Pages ในเบราว์เซอร์ → ตรวจเลขเวอร์ชันใหม่ + ลองฟีเจอร์ที่แก้ (คลิก/พิมพ์/สั่ง PDF) + ดู console ไม่มี error → แนบภาพผลในสรุป · ไม่ต้องรอให้ลุงพีสั่ง
- โปรแกรมใหม่ทุกตัว: **ไอคอน .ico ของตัวเอง + shortcut .lnk บน Desktop** (สคริปต์ make-shortcut รันซ้ำได้ทั้ง 2 เครื่อง)

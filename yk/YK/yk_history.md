## 3. การตัดสินใจสำคัญ + เหตุผล

### สัญญาณที่เพิ่ม (ผ่าน split-half test)
- **⑨ จีบท้าย**: คู่จีบ 3-4 รอบก่อน → แถวที่ 3 = 36.7% (บวกทั้ง 2 ครึ่ง)
- **⑩ เลขเรียง (ขึ้น+ลง)**: 3 รอบถัดไป any-3 = 71.8% (lift 1.09). เรียงลง (73.1%) เสถียรกว่าเรียงขึ้น (70.5%) แต่รวมกันเสถียรทั้ง 2 ครึ่ง — เรียงขึ้นเดี่ยวไม่เสถียร (66.7%/75.0%) จึงต้องรวม
- **⑪ ล่างเด่น 97/78/69**: 3 รอบถัดไป 75.8% (lift 1.14) · **ล่างเย็น 95**: 54.7% (lift 0.80 → −1)

### สัญญาณ/แนวคิดที่ทดสอบแล้ว "ไม่เพิ่ม" (ยึดหลัก: ต้องดีขึ้นก่อนถึงใส่)
- **ช่องทำนายแบบ real-time (3 แถวจริงล่าสุด)**: ทำให้ precision *แย่ลง* (28.6% vs 30.1%) เพราะ P(OK|OK)≈P(OK|notOK) เกมสุ่มอิสระ — **ไม่ผนวก**
- **ประเภท OK อื่น** (หาม/คู่หน้า/คู่หลัง/ตอง): ไม่เสถียร split-half — **ไม่เพิ่มเป็นคะแนน** แสดงแค่กรอบเหลืองจาง (visual)
- **กลุ่มเลขล่าง 33 ตัว โดยรวม**: ไม่มีผล (ครอบคลุม 1/3 ของเลขอยู่แล้ว เฉลี่ยกลับ baseline)

### การค้นพบเชิงหลักการ
- **หลัง OK ออก → 3 รอบถัดไป โอกาส OK เท่าเดิมเป๊ะ** (65.9% = baseline) — เกม independent, "ออกแล้วออกอีก" เป็นความเชื่อผิด
- สิ่งที่มีผลจริงคือ **"ประเภท" ของ OK** (เลขเรียง) ไม่ใช่ "การมี OK"
- **ช่องทำนาย** = จังหวะ Markov chain (ภาพรวม) · **ช่องคะแนน** = หลักฐานสดรายรอบ (ใช้ตัดสินซื้อ) → เวลาซื้อดู score ≥ 4 เป็นหลัก

### ช่องทำนาย boost (เพิ่มแล้ว — ดีขึ้นเล็กน้อย)
- หลังเลขเรียง 3 แถว → ×1.10 · Precision 30.1%→30.3%, Recall +0.4pp · แสดง ⑩▲

## 3c. ช่องทำนาย real-time ผสมหลัง-OK (2026-09-17)
ช่องทำนาย = Markov (เขียว) **ผสม** หลักคิดหลัง-OK (เหลือง): เมื่อ OK set ออก → หน้าต่าง 6 แถวถัดไปดันความถี่ทำนาย OK ให้ครบ 3 แถว (เติมแถว pMarkov สูงสุดที่ Markov ไม่ได้เลือก). real-time ตามผลจริง (computeAfterOK ใน computeAnalysis). ค่าคงที่ AFTER_OK_WINDOW=6, AFTER_OK_TARGET=3. ช่องรอบที่จะซื้อเพิ่ม badge เหลือง "🟡 ซื้อ (หลัง OK)"
- **ผลทดสอบ test3 (โปร่งใส):** Markov เดิม Acc 58.7% Prec 27.7% Rec 28.0% → ผสม Acc 44.1% Prec 28.2% Rec 62.2%. Recall เพิ่มมาก แต่ Precision ของแถวเหลือง ≈ baseline 28.5% (หลัง OK ไม่มี edge จริง) และ Accuracy ลดเพราะทำนาย OK เยอะขึ้น (28.8%→62.8%)
- **หมายเหตุ:** หน้าต่างซ้อนกัน (OK ออก ~ทุก 3 แถว) ทำให้บางช่วงได้ >3/6 · Markov + seqBoost(⑩▲) คงไว้ตามเดิม
- **แถบสถิติแยก 2 ช่อง:** 🟢 Markov ล้วน (แม่น/Acc/ทำนาย%) vs 🟡 ผสม+หลัง OK — เทียบได้ทันทีว่า precision ทั้งคู่ ≈ baseline แต่ผสมดันทำนาย OK สูงขึ้นแลกกับ Acc ต่ำลง

## 3k. แก้ Bug parseCSVRobust + ทดสอบ CSV 30 วันใน Predictor (2026-09-17, v19)

### Bug: parseCSVRobust อ่าน column ผิด
**ปัญหา**: CSV format `วันที่,รอบ,เวลา,3 ตัวบน,...` — parser เดิมอ่าน `รอบ` (1,2,3) เป็น `up3` แทนที่จะเป็นผลสลากจริง ทำให้ Markov chain สร้างจากเลขลำดับรอบ ไม่ใช่ผล 3 ตัวบน

**แก้ไข**: เพิ่ม header-aware parsing ใน `parseCSVRobust`:
- ตรวจ header row — ถ้ามี `วันที่` หรือ `3 ตัวบน` → ใช้ column index ที่อ่านจาก header โดยตรง
- `colRound` = index ของ `รอบ` · `colUp3` = index ของ `3 ตัวบน` · `colLow2` = index ของ `2 ตัวล่าง`
- ข้าม header row (startLi = 1) · fallback heuristic สำหรับ CSV ไม่มี header
